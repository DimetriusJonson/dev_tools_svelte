# WebDev Useful Tools

Кроссплатформенное desktop-приложение с набором инструментов для веб-разработчика: форматирование XML/JSON, экранирование текста, работа с URL, сравнение фрагментов, обмен файлами по локальной сети и обработка файлов.

Приложение работает как Tauri v2 desktop-клиент с frontend на SvelteKit. В обычном браузере доступна клиентская часть инструментов; нативные диалоги, SQLite и обработка больших файлов доступны в desktop-сборке.

## Возможности

- **XML / JSON** — форматирование с отступом 2, 3 или 4 пробела, деэкранирование, экранирование, копирование и сохранение результата.
- **Обработка файлов (desktop)** — выбор файла через нативный диалог, форматирование на Rust-бэкенде и запись результата в выбранный файл.
- **URL** — кодирование и декодирование URL, копирование и сохранение результата.
- **Compare** — построчное и inline-сравнение двух текстов с подсветкой различий, статистикой и сменой сторон.
- **Share (desktop)** — загрузка файла или содержимого в локальную базу, read-only HTTP-сервер в локальной сети и deep link, открывающий встроенный просмотрщик на другом устройстве.
- **Rest client** — проекты и сохранённые HTTP-запросы, импорт cURL из буфера обмена, заголовки/query/cookies, тело JSON/XML/Text/Form-encode, выполнение запроса на бэкенде, просмотр ответа, заголовков и отправленного запроса.
- **Темы** — системная, тёмная и светлая.
- **Локализация** — русский и английский языки; заголовок окна и вкладки меняется вместе с локалью и содержит текущую версию приложения (`0.1.0`).
- **Desktop-интеграция** — системный трей, запуск в единственном экземпляре, скрытие окна в трей, нативные файловые диалоги.
- **Сохранение состояния** — содержимое редакторов и опции сохраняются в SQLite, вне Tauri используется `localStorage`.

Все ошибки и подтверждения копирования показываются всплывающими уведомлениями внизу окна.

## Быстрый старт

Требования:

- Node.js 20+;
- Rust stable;
- системные зависимости Tauri v2 для вашей ОС.

Установка зависимостей и запуск в режиме разработки:

```bash
npm install
npm run tauri dev
```

Запуск только frontend:

```bash
npm run dev
```

Сборка frontend и desktop-приложения:

```bash
npm run build
npm run tauri build
```

Если в окружении не хватает Linux-зависимостей Tauri, установите их через пакетный менеджер вашей системы.

## Страницы

### XML / JSON

Единый компонент `XmlJsonFormatter.svelte` используется для страниц `/xml` и `/json`.

- Слева — редактируемый CodeMirror с подсветкой синтаксиса.
- В центре — выбор отступа, чекбоксы «Форматировать» и «Деэкранировать», кнопка запуска и кнопка «Экранировать».
- Между левой и правой панелью — перетаскиваемый вертикальный разделитель.
- Справа — read-only CodeMirror с результатом, копированием в буфер и сохранением в файл.
- Внизу — выбор файла и кнопка форматирования файла на бэкенде.

Клиентское форматирование выполняется в браузере: JSON разбирается через `JSON.parse`, XML — через `DOMParser`. Для XML сохраняется объявление `<?xml ...?>`, а спецсимволы сериализуются предсказуемо.

В Tauri-режиме обработка файла выполняется командой `process_large_file`. XML обрабатывается потоково через `quick-xml` (кроме режима деэкранирования, когда файл читается целиком), JSON разбирается в `serde_json::Value` и сериализуется с точным отступом. Результат сначала пишется во временный файл, затем копируется в выбранное место.

### URL

- Сверху — исходная строка в `<textarea>`.
- В центре — перетаскиваемый горизонтальный разделитель и кнопки «Кодировать» / «Декодировать».
- Снизу — read-only `<textarea>` с результатом, копированием и сохранением.

Кодирование использует `encodeURI`, декодирование — `decodeURI`. Это сохраняет структуру URL (`https://`, `?`, `&` и другие зарезервированные символы). При некорректной последовательности возвращается исходная строка.

### Compare

- Два CodeMirror-редактора: исходный и сравниваемый текст.
- Кнопка «Сравнить» запускает построчное LCS-сравнение.
- Добавленные, удалённые и изменённые строки подсвечиваются; внутри изменённых строк дополнительно подсвечиваются отличающиеся фрагменты.
- Показывается статистика: добавлено, удалено, изменено.
- Кнопка со стрелками меняет стороны местами.
- Состояние обеих панелей сохраняется отдельно.

Для очень больших входных данных сравнение автоматически переходит к более дешёвому сравнению по префиксу/суффиксу и подсветке целых строк, чтобы не блокировать интерфейс.

### Share

Share доступен в desktop-сборке и работает в локальной сети без внешнего сервера.

- На странице `/share` выбирается сетевой интерфейс и адрес вида `http://192.168.x.x:3030`.
- Файл можно выбрать в нативном диалоге или перетащить в окно; перетаскивание сразу запускает загрузку.
- Режим «Содержимое» принимает XML, JSON или обычный текст из CodeMirror. Содержимое, присланное кнопкой Share из результата XML/JSON, показывается в нередактируемом редакторе: правки нужно делать в исходном инструменте.
- Лимит одной загрузки — 50 MB. Данные сохраняются в SQLite в таблице `shared_uploads` под UUID v4.
- После загрузки приложение показывает deep link `webdev-useful-tools://view?server=...&id=...`.
- Ссылка открывает desktop-приложение на другом устройстве и страницу `/view`, где XML/JSON/текст показываются в read-only CodeMirror, а двоичный файл — с метаданными и кнопкой скачивания.
- HTTP-сервер слушает `0.0.0.0:3030`, пока приложение запущено, и предоставляет только чтение: `GET /health`, `GET /api/uploads/{uuid}`, `GET /api/uploads/{uuid}/raw`.
- Если сервер не запущен (например, порт 3030 занят другим процессом), загрузка блокируется, а на странице появляется кнопка «Повторить запуск сервера».

Загрузка возможна только из интерфейса приложения. Внешние клиенты не могут создавать записи через HTTP. Если приложение-источник закрыто, сервер и ссылки недоступны. Если приложение не установлено на устройстве получателя, deep link не откроется.

Кнопка Share в результате XML/JSON передаёт отформатированный текст на страницу `/share` в режиме только для чтения.

### Rest client

Страница `/rest` — полноценный HTTP-клиент с сохранением запросов в SQLite.

- **Проводник запросов**: выпадающий список проектов с меню «Создать / Переименовать / Удалить», кнопка «Создать», импорт cURL из буфера обмена и список запросов с методом и названием (если названия нет — URL).
- **Меню запроса** открывается кнопкой «...» или правой кнопкой мыши: «Выполнить», «Копировать cURL», «Копировать cURL.exe», «Переименовать», «Дублировать», «Удалить».
- **Панель запроса**: выбор HTTP-метода, URL и кнопка выполнения с вращающимся глобусом. Повторное нажатие во время выполнения прерывает запрос и показывает уведомление «Запрос прерван».
- **Вкладки запроса**: `Headers`, `Query`, `Cookies`. Изменения в `Query` сразу перестраивают URL, изменения в `Cookies` сразу обновляют заголовок `Cookie`.
- **Body**: вкладки `JSON`, `XML`, `Text`, `Form-encode`. Для JSON/XML доступна кнопка форматирования в панели вкладок; Form-encode редактируется таблицей параметров. Таблица `Form-encode` независима от текстового тела: переключение вкладок не переносит строки таблицы в тело JSON/XML/Text и не заполняет таблицу из тела. При выполнении запроса с активной вкладкой `Form-encode` тело запроса строится из таблицы (приоритет таблицы), а текстовое тело игнорируется; пустая таблица означает запрос без тела. Для тела ставится `Content-Type: application/x-www-form-urlencoded`, если заголовок не задан вручную. При импорте cURL с `application/x-www-form-urlencoded` таблица заполняется из тела импортируемого запроса, а текстовый буфер остаётся пустым.
- **Ответ**: вкладки `Response`, `Headers`, `Raw request`. Верхняя панель показывает статус, размер (`bytes`/`KiB`/`MiB`) и время (`ms`/`sec` с двумя знаками), а также кнопки форматирования/деэкранирования для XML/JSON, предпросмотра HTML, скачивания вложения и копирования тела.
- **Сохранение ответа**: чекбокс `Save` доступен только для текстовых ответов и сохраняется вместе с запросом. Ответ, заголовки ответа и отправленный запрос восстанавливаются при следующем открытии запроса.
- **Вложения и бинарные ответы**: при `Content-Disposition: attachment` тело не загружается заранее; показывается кнопка скачивания. Двоичные ответы также не рендерятся в редакторе.
- **Raw request**: показывает фактически отправленный запрос; кнопки копируют его как `cURL` для POSIX и как `cURL.exe` для Windows.
- **Разделители**: перетаскиваемые вертикальные разделители между проводником и правой областью и между конфигурацией запроса и ответом, а также горизонтальный разделитель между параметрами и телом.

В desktop-сборке запрос выполняет Rust-бэкенд, поэтому CORS не ограничивает клиент. В браузере используется `fetch` с ограничениями браузера: часть заголовков недоступна, а ответы подчиняются CORS. В браузере данные запросов сохраняются в `localStorage` под ключом `devtools.rest`.

Ограничения клиента: таймаут запроса — 120 секунд, поддерживаются HTTP и HTTPS, редиректы ограничены 10 переходами. Запросы, тела и сохранённые ответы хранятся в базе приложения и не синхронизируются между устройствами. У запросов, сохранённых до разделения вкладок тела, в текстовом буфере может оставаться закодированная строка Form-encode: при активной вкладке `Form-encode` она не отправляется, приоритет у таблицы.

## Навигация, темы и язык

- Верхняя панель содержит вкладки XML, JSON, URL, Compare, Share и Rest client.
- Кнопки навигации увеличиваются при наведении (`hover:scale-105`); подсветка фона при наведении не используется.
- Переключатель языка: `en` / `ru`. По умолчанию выбирается системный язык: `ru`, если локаль ОС начинается с `ru`, иначе `en`.
- Переключатель темы циклически меняет режимы `system → dark → light`. По умолчанию используется `system`.
- Выбор языка и темы сохраняется в `localStorage`.

## Сохранение данных

В Tauri-режиме база данных создаётся в app data directory приложения:

```text
webdev-useful-tools.db
```

Используются таблицы:

- `editor_state` — содержимое и опции редакторов;
- `app_settings` — key/value-настройки (команды доступны, тема и язык сейчас хранятся в `localStorage`);
- `shared_uploads` — общие файлы и текстовые фрагменты: UUID, имя, MIME-тип, BLOB, размер и время создания;
- `rest_projects` — проекты Rest client;
- `rest_requests` — сохранённые запросы: метод, URL, текстовое тело (буфер вкладок JSON/XML/Text), тип тела, флаг сохранения ответа, сохранённый ответ и отправленный запрос;
- `rest_request_properties` — HTTP-заголовки запроса (тип `header`);
- `rest_request_form` — строки таблицы вкладки `Form-encode` (`name`, `value`, порядок). Они хранятся отдельно от текстового тела, и закодированное тело больше не дублируется в `rest_requests.body`.

Проекты, запросы, заголовки и Form-encode параметры Rest client хранятся в отдельных таблицах. Удаление проекта не удаляет запросы: они остаются в списке без привязки к проекту (`project_id = NULL`), а фильтр проектов показывает «Не выбран». Удаление запроса удаляет его заголовки и строки Form-encode.

Ключи `editor_state`:

- `xml`, `json` — исходный контент, отступ и чекбоксы;
- `url` — исходная строка;
- `compare-left`, `compare-right` — обе стороны сравнения.

Сохранение выполняется с задержкой 450 мс после изменения (в Compare — 500 мс). Если приложение запущено вне Tauri, используется `localStorage` с префиксами `devtools.editor.` и `devtools.setting.`.

## Desktop-интеграция

- **Single instance** — второй экземпляр приложения фокусирует и разворачивает уже открытое окно.
- **Трей** — пункты «Открыть» и «Выход».
- **Закрытие окна** — скрывает окно в трей; полностью приложение завершается через «Выход» в трее.
- **Файловые диалоги** — `@tauri-apps/plugin-dialog`.
- **Share-сервер** — `axum` слушает `0.0.0.0:3030` и отдаёт только GET-запросы.
- **Deep links** — схема `webdev-useful-tools` регистрируется через `tauri-plugin-deep-link`; второй экземпляр передаёт ссылку уже запущенному приложению через `single-instance` с feature `deep-link`.
- **Иконки** — исходник `src-tauri/icon-source.png`, SVG-версия `src-tauri/icons/app-icon.svg`; набор иконок сгенерирован через `npx tauri icon`.

Размер окна по умолчанию — 1440×920, минимальный — 1100×700.

## Тестирование

```bash
npm run test
npm run check
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

Frontend-тесты покрывают форматирование XML/JSON, экранирование/деэкранирование, URL encode/decode, diff, share-утилиты (размер файла, URL просмотрщика) и Rest-утилиты (query/cookies/form, импорт и экспорт cURL, размер и время ответа). Rust-тесты покрывают SQLite, маппинг действий трея, форматирование контента, обработку файлов, share-хранилище, deep link validation, состояние HTTP-сервера, CRUD проектов и запросов Rest client и round trip `reqwest` по plain HTTP.

## Ограничения

- Share работает только в desktop-приложении и только с устройствами, которые могут достучаться до `0.0.0.0:3030` в локальной сети. Loopback-адрес доступен только на самом устройстве.
- HTTP-сервер Share не использует авторизацию: любой, кто знает UUID и адрес, может прочитать загрузку, пока приложение запущено. Ссылки не следует публиковать во внешних сетях.
- Загрузки Share не удаляются автоматически и не имеют TTL.
- Возможности Rest client в браузере ограничены CORS и запрещёнными заголовками; для полноценной работы используйте desktop-сборку.
- Rest client хранит сохранённые ответы в SQLite без ограничения размера; очень большие ответы могут замедлить интерфейс.
- Обработка больших файлов доступна только в Tauri-сборке.
- Compare использует ограниченный по памяти LCS и для очень больших блоков применяет упрощённое сравнение.
- Тема и язык хранятся в `localStorage`, а не в SQLite.
