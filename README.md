# WebDev Useful Tools

Кроссплатформенное desktop-приложение с набором инструментов для веб-разработчика: форматирование XML/JSON, экранирование текста, работа с URL, сравнение фрагментов, обмен файлами по локальной сети и обработка файлов.

Приложение работает как Tauri v2 desktop-клиент с frontend на SvelteKit. В обычном браузере доступна клиентская часть инструментов; нативные диалоги, SQLite и обработка больших файлов доступны в desktop-сборке.

## Возможности

- **XML / JSON** — форматирование с отступом 2, 3 или 4 пробела, деэкранирование, экранирование, копирование и сохранение результата.
- **Обработка файлов (desktop)** — выбор файла через нативный диалог, форматирование на Rust-бэкенде и запись результата в выбранный файл.
- **URL** — кодирование и декодирование URL, где декодирование сначала разворачивает HTML-сущности, копирование и сохранение результата.
- **Compare** — построчное и inline-сравнение двух текстов с подсветкой различий, статистикой и сменой сторон.
- **Share (desktop)** — загрузка файла или содержимого в локальную базу с выбором срока хранения (от «не хранить» до «всегда»), сгенерированная ссылка на отдельной вкладке «Ссылка», HTTP-сервер в локальной сети, deep link, открывающий встроенный просмотрщик на другом устройстве, и кнопка удаления загрузки из просмотрщика.
- **Rest client** — проекты и сохранённые HTTP-запросы, импорт cURL из буфера обмена, заголовки/query/cookies, тело JSON/XML/Text/Form-encode/Form (multipart с полями и файлами), выполнение запроса на бэкенде, просмотр ответа, заголовков и отправленного запроса, и восстановление открытых вкладок каждой панели при повторном открытии запроса.
- **WSDL-клиент (desktop)** — импорт файла WSDL 1.1 по адресу из буфера обмена, дерево `файл → служба → операция`, шаблон запроса по XSD-схеме, выбор `soap:address`, таблица заголовков с незаменяемыми строками привязки, предпросмотр `Raw`, сборка SOAP-конверта (1.1 и 1.2), выполнение через Rust-бэкенд Rest client и просмотр ответа, его заголовков и сырого обмена.
- **Глобальные переменные (desktop)** — именованные значения, которые подставляются в запросы как `{{ name }}`: значения query-параметров, заголовков, тела и полей формы. Обычное значение лежит в SQLite, безопасное — в системном хранилище секретов и в дампе отправленного запроса показывается как `********`.
- **Темы** — системная, тёмная и светлая.
- **Обновления (desktop)** — автопроверка при старте и кнопка в верхней панели, баннер с версией, примечаниями релиза и прогрессом загрузки, установка через подписанный установщик Windows в режиме `passive`.
- **Локализация** — русский и английский языки; заголовок окна и вкладки меняется вместе с локалью и содержит текущую версию приложения (`0.2.0`).
- **Desktop-интеграция** — системный трей, запуск в единственном экземпляре, скрытие окна в трей, нативные файловые диалоги.
- **Сохранение состояния** — содержимое редакторов и опции сохраняются в SQLite, вне Tauri используется `localStorage`.

Все ошибки и подтверждения копирования показываются всплывающими уведомлениями внизу окна: текст сообщения выровнен по центру, кнопка закрытия закреплена справа и не перекрывает длинные сообщения.

- **Tailwind CSS**.

- **Vitest** — frontend unit-тесты.

## Быстрый старт

Требования:

- Node.js 20+;
- Rust stable;
- системные зависимости Tauri v2 для вашей ОС.

Установка зависимостей и запуск в режиме разработки:

```bash
npm install
npm run tauri dev
```

Запуск только frontend:

```bash
npm run dev
```

Сборка frontend и desktop-приложения:

```bash
npm run build
npm run tauri build
```

Если в окружении не хватает Linux-зависимостей Tauri, установите их через пакетный менеджер вашей системы.

## Скрипты

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Vite dev server на `http://localhost:1420` |
| `npm run build` | Сборка SvelteKit в `build/` |
| `npm run preview` | Предпросмотр production-сборки |
| `npm run check` | `svelte-kit sync` + `svelte-check` |
| `npm run test` | Unit-тесты Vitest |
| `npm run test:watch` | Vitest в watch-режиме |
| `npm run tauri dev` | Запуск desktop-приложения |
| `npm run tauri build` | Сборка desktop-приложения и установщика |

Сборка с артефактами обновлений требует ключ подписи (публичный ключ уже прописан в `src-tauri/tauri.conf.json > plugins > updater > pubkey`):

```bash
npx tauri signer generate -w ~/.tauri/webdev-useful-tools.key --ci   # однократно, без пароля
TAURI_SIGNING_PRIVATE_KEY=~/.tauri/webdev-useful-tools.key npm run tauri build
git tag v0.2.0 && git push origin v0.2.0   # релиз собирает GitHub Actions
```

Приватный ключ (`~/.tauri/webdev-useful-tools.key`) в репозиторий не попадает. Если ключ защищён паролем, добавьте `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Сборка с `bundle.createUpdaterArtifacts: true` кладёт рядом с установщиком файл `.sig` и манифест `latest.json` — их нужно приложить к релизу GitHub вместе с самим установщиком, иначе проверка отвечает «Обновлений не найдено».

Релиз собирает GitHub Actions: `.github/workflows/release.yml` запускается по тегу вида `v<версия>` (или вручную, тогда артефакты лягут только в workflow, без релиза). Проверка гоняет `npm run test`, `npm run check` и `cargo test`, требует одинаковой версии в `package.json`, `tauri.conf.json` и `Cargo.toml`, совпадения тега с версией приложения и наличия секрета репозитория `TAURI_SIGNING_PRIVATE_KEY`. Дальше четыре сборки — Windows `.msi`, Linux `.deb`/`.AppImage`, macOS `.dmg` + `.app.tar.gz` для Intel и Apple Silicon — идут строго по очереди: каждая дописывает `latest.json` предыдущей, и параллель они потеряли бы запись своей платформы. Артефакты и `.sig` выкладываются в черновик релиза, отдельная задача проверяет, что манифест содержит все четыре платформы и подписи, и только затем публикует релиз как «последний». Повтор уже опубликованного тега падает намеренно: сборщик артефактов не присоединяется к опубликованному релизу с тем же тегом, поэтому вместо повтора нужно выпустить новую версию.

Rust-тесты:

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

## Страницы

### XML / JSON

Единый компонент `XmlJsonFormatter.svelte` используется для страниц `/xml` и `/json`.

- Слева — панель исходного текста: в её шапке находятся выбор файла, имя выбранного файла и кнопка форматирования файла на бэкенде, ниже — редактируемый CodeMirror с подсветкой синтаксиса.
- В центре — выбор отступа, чекбоксы «Форматировать» и «Деэкранировать», кнопка запуска и кнопка «Экранировать».
- Между левой и правой панелью — перетаскиваемый вертикальный разделитель.
- Справа — панель результата с такой же шапкой: кнопки Share, копирования в буфер и сохранения в файл, ниже — read-only CodeMirror.

Клиентское форматирование выполняется в браузере: JSON разбирается через `JSON.parse`, XML — через `DOMParser`. Для XML сохраняется объявление `<?xml ...?>`, а спецсимволы сериализуются предсказуемо.

Корректная разметка форматируется строго. Если строгий разбор падает — текст или перенос строки перед `<?xml ...?>`, несколько корневых элементов, незакрытый или лишний закрывающий тег, лишняя запятая или незакрытая скобка в JSON — кнопка «Форматировать» не показывает ошибку, а переставляет отступы, не меняя сам текст: элемент без закрывающего тега сериализуется как `<a/>`, лишний `</x>` остаётся отдельной строкой, незакрытые скобки не дописываются, а текст внутри разметки и строки JSON не переэкранируются (то есть `&lt;` и `&amp;` остаются как в исходнике, а не разворачиваются и не удваиваются). Мусор до или после JSON-документа (`aaa` перед `{"userId":…}`) остаётся отдельной строкой, а сам документ форматируется строго, как корректный JSON. Ошибка «Не удалось обработать содержимое…» остаётся только для текста, в котором нет ни разметки, ни JSON-структуры: `hello world`, обычный текст в режиме XML или HTML-страница в режиме JSON. В режиме «Деэкранировать» для битого содержимого выбирается тот вариант (исходник или деэкранированный), в котором больше разметки или структурных символов JSON.

В Tauri-режиме обработка файла выполняется командой `process_large_file`. XML обрабатывается потоково через `quick-xml` (кроме режима деэкранирования, когда файл читается целиком), JSON разбирается в `serde_json::Value` и сериализуется с точным отступом. Потоковый разбор проверяет форму документа: мусор вне корневого элемента, второй корень, незакрытый элемент или `</x>` без соответствующего элемента отклоняются, и тогда файл перечитывается и форматируется тем же толерантным способом, что и текст в браузере; для JSON резервный путь тот же, что и в браузере. Результат сначала пишется во временный файл, затем копируется в выбранное место.

Критерии проверки: текст `aaa` перед `<?xml ...?>` и корректным `<catalog>` форматируется без ошибки — `aaa` остаётся отдельной строкой выше объявления, элементы внутри `<catalog>` получают выбранный отступ; текст `aaa` перед корректным объектом JSON тоже форматируется без ошибки — `aaa` остаётся первой строкой, объект разворачивается с выбранным отступом; `<root><a></root>` превращается в `<root>` с `<a/>` внутри; `<a><b><c>d` закрывается там, где закрылся бы родитель; `{"a":1,}` и `[{"a":[1,2]` форматируются без ошибки; `hello world` в режимах XML и JSON по-прежнему показывают уведомление об ошибке, и результат не перезаписывается.

### URL

- Сверху — исходная строка в `<textarea>`.
- В центре — перетаскиваемый горизонтальный разделитель и кнопки «Кодировать» / «Декодировать».
- Снизу — read-only `<textarea>` с результатом, копированием и сохранением.

Кодирование и декодирование используют `encodeURIComponent`/`decodeURIComponent`: кодируются и раскрываются все символы вне набора unreserved, включая зарезервированные (`:` `/` `?` `&` `=`). Поэтому `http://10.7.6.86:3030&id=…` кодируется в `http%3A%2F%2F10.7.6.86%3A3030%26id%3D…`, а не остаётся структурой URL, как делает `encodeURI`, и то же значение обратно декодируется — `decodeURI` такие коды не раскрывает.

Декодирование работает в два шага — в том порядке, в котором ссылка приходит из HTML-разметки: сначала разворачиваются HTML-сущности (`&amp;` → `&`, `&lt;` → `<`, `&#39;` → `'`), затем процент-коды (`%5C` → `\`). Сущности разворачиваются один раз и именно до процент-кодов, поэтому закодированная сущность (`%26amp%3B`) остаётся текстом `&amp;`, а не превращается в `&`: декодирование остаётся точной обратной операцией к кодированию. При некорректной процент-последовательности возвращается текст после первого шага — развёрнутые сущности не теряются; если в строке нет ни сущностей, ни процент-кодов, она возвращается без изменений.

Критерии проверки: `http://10.7.6.86:3030&id=8f82124b-cd30-42ed-84a6-1b8567810614` кодируется в `http%3A%2F%2F10.7.6.86%3A3030%26id%3D8f82124b-cd30-42ed-84a6-1b8567810614`; `https://example.com/a b?x=1&y=привет` возвращается обратно после кодирования и декодирования; `http%3A%2F%2F10.7.6.86%3A3030&id=…` декодируется в `http://10.7.6.86:3030&id=…`; ссылка из разметки `…?format=pdf&amp;is_empty=1&amp;…&amp;Contract_Number=11472%5C2026%5C1&amp;filename=StatementOfAcceptance.pdf` декодируется в `…?format=pdf&is_empty=1&…&Contract_Number=11472\2026\1&filename=StatementOfAcceptance.pdf`; `%26amp%3B` остаётся `&amp;`, а `&amp;#92;` — `&#92;`; `%E0%A4%A` и `100%` остаются без изменений, а `&amp;100%` декодируется в `&100%`.

### Compare

- Два CodeMirror-редактора: исходный и сравниваемый текст.
- Кнопка «Сравнить» запускает построчное LCS-сравнение.
- Добавленные, удалённые и изменённые строки подсвечиваются; внутри изменённых строк дополнительно подсвечиваются отличающиеся фрагменты.
- Показывается статистика: добавлено, удалено, изменено.
- Кнопка со стрелками меняет стороны местами.
- Состояние обеих панелей сохраняется отдельно.

Для очень больших входных данных сравнение автоматически переходит к более дешёвому сравнению по префиксу/суффиксу и подсветке целых строк, чтобы не блокировать интерфейс.

### Share

Share доступен в desktop-сборке и работает в локальной сети без внешнего сервера.

- На странице `/share` выбирается сетевой интерфейс и адрес вида `http://192.168.x.x:3030`.
- Файл можно выбрать в нативном диалоге или перетащить в окно; перетаскивание сразу запускает загрузку.
- Режим «Содержимое» принимает XML, JSON или обычный текст из CodeMirror. Содержимое, присланное кнопкой Share из результата XML/JSON, показывается в нередактируемом редакторе: правки нужно делать в исходном инструменте.
- Лимит одной загрузки — 50 MB. Загрузка получает UUID v4 и ложится в SQLite в таблицу `shared_uploads`, если выбран срок хранения; «Не хранить» не пишет в базу ничего.
- **Срок хранения** выбирается в списке «Хранить» и сохраняется в настройку `share.retention`, поэтому при следующем запуске приложения выбранное значение остаётся: «Не хранить», «1 день», «3 дня», «7 дней», «Всегда». Значение по умолчанию — «Не хранить»: пока срок не выбран явно, загрузка не пишется в базу.
- «Не хранить» не пишет загрузку в базу: содержимое живёт только в памяти приложения (не более 24 последних загрузок, самая старая вытесняется), и ссылка перестаёт работать после закрытия приложения. «1 день», «3 дня» и «7 дней» сохраняют загрузку с временем окончания, «Всегда» — без него.
- Просроченные записи не отдаются по ссылке и удаляются из базы при следующей загрузке, открытии ссылки или старте сервера — отдельного таймера нет.
- После загрузки приложение показывает deep link `webdev-useful-tools://view?server=...&id=...` в отдельной вкладке «Ссылка» рядом с «Файл» и «Содержимое»: она появляется после успешной загрузки и сразу становится активной, поэтому прокручивать страницу к ссылке не нужно. Под ссылкой — срок хранения, «до какой даты доступна загрузка» или пояснение, что содержимое только в памяти, и размер.
- Вкладка «Ссылка» существует, пока есть загрузка: выбор нового файла или неудачная загрузка убирает её и возвращает страницу на вкладку «Файл». На вкладке «Ссылка» список срока хранения не показывается — он влияет только на новую загрузку.
- Ссылка открывает desktop-приложение на другом устройстве и страницу `/view`, где XML/JSON/текст показываются в read-only CodeMirror, а двоичный файл — с метаданными и кнопкой скачивания. Просмотрщик показывает срок хранения (`Доступно до` или «До удаления»), а для загрузки только в памяти — предупреждение с значком.
- **Удаление загрузки**: в просмотрщике есть кнопка «Удалить эту загрузку» (иконка корзины в панели кода и кнопка в карточке двоичного файла). Она требует подтверждения прямо на странице — строка с текстом «Удалить эту загрузку? Ссылка перестанет работать у всех.» и кнопки «Удалить» / «Отмена». После удаления содержимое убрано из базы (или из памяти), просмотрщик показывает «Загрузка удалена. Ссылка больше не работает.», а `GET` по той же ссылке отвечает 404.
- HTTP-сервер слушает `0.0.0.0:3030`, пока приложение запущено: `GET /health`, `GET /api/uploads/{uuid}`, `GET /api/uploads/{uuid}/raw` и `DELETE /api/uploads/{uuid}` (204 при успехе, 404 для неизвестного или битого ID). У ссылки нет секрета, поэтому удалить загрузку может тот, кто открыл ссылку.
- Если сервер не запущен (например, порт 3030 занят другим процессом), загрузка блокируется, а на странице появляется кнопка «Повторить запуск сервера».

Загрузка возможна только из интерфейса приложения: внешние клиенты не могут создавать записи через HTTP. У ссылки нет пароля и токена, поэтому прочитать и удалить загрузку может любой, кто открыл ссылку в локальной сети. Если приложение-источник закрыто, сервер и ссылки недоступны — в том числе ссылки с «Не хранить». Если приложение не установлено на устройстве получателя, deep link не откроется.

Кнопка Share в результате XML/JSON передаёт отформатированный текст на страницу `/share` в режиме только для чтения.

Критерии проверки: список «Хранить» предлагает «Не хранить», «1 день», «3 дня», «7 дней», «Всегда» и по умолчанию стоит «Не хранить»; выбранное значение переживает перезапуск приложения, а неизвестное сохранённое значение читается как «Не хранить». Вкладка «Ссылка» появляется только после успешной загрузки, становится активной сама, содержит поле ссылки с кнопкой копирования и подпись срока; после выбора нового файла или неудачной загрузки она исчезает, а активной остаётся вкладка «Файл». Активная вкладка помечена `aria-pressed`, поэтому она различима не только по цвету. В браузерной сборке страница показывает только предупреждение о desktop-версии без кнопок загрузки и без строки «Запуск сервера обмена…». Загрузка с «Всегда» отдаётся по ссылке без даты окончания, с «1 день» — с `expires_at` примерно через сутки; после `DELETE /api/uploads/{id}` загрузка убрана, повторные `GET` и `DELETE` отвечают 404, а `DELETE` уже просроченной, но ещё лежащей в базе записи отвечает 204 и стирает строку — удаление не блокируется фильтром по сроку. Загрузка с «Не хранить» не создаёт строку в `shared_uploads`, сервер отдаёт её из памяти, подпись под ссылкой говорит о памяти, а после удаления или закрытия приложения ссылка перестаёт работать. В просмотрщике первая кнопка «Удалить» только открывает подтверждение и ничего не удаляет; «Отмена» оставляет загрузку на месте, а «Удалить» убирает её и показывает «Загрузка удалена. Ссылка больше не работает.». Кнопка удаления появляется только у открытой загрузки, а подтверждение — прямо на странице, без `window.confirm`.

### Rest client

Страница `/rest` — полноценный HTTP-клиент с сохранением запросов в SQLite.

- **Проводник запросов**: выпадающий список проектов с меню «Создать / Переименовать / Удалить», кнопка «Создать», импорт cURL из буфера обмена и список запросов с методом и названием (если названия нет — URL). Активный запрос подсвечен фоном с оттенком акцента и левой полосой акцентного цвета, при наведении строка подсвечивается нейтральным фоном: подсветка заметно отличается от фона панели в обеих темах.
- **Восстановление выбора**: выбранные проект и запрос сохраняются сразу после изменения выбора в SQLite (`app_settings`, ключи `rest.activeProject` и `rest.activeRequest`; пустая строка означает «ничего не выбрано»), а в браузерной сборке — в `localStorage` под префиксом `devtools.setting.`. После запуска приложения открыты тот же проект и тот же запрос. Если сохранённый запрос удалён, выбирается первый запрос видимого списка; если удалён проект, открывается список «Не выбран» со всеми запросами; если сохранённый запрос принадлежит другому проекту, проводник переходит в тот проект, чтобы строка была видна в списке.
- **Открытые вкладки**: какая вкладка запроса (`Headers`, `Query`, `Cookies`, `Raw`), какая из вложенных вкладок `Form` (`Поля`, `Файлы`) и какая вкладка ответа (`Response`, `Headers`, `Raw`) были открыты, сохраняются вместе с запросом: в SQLite — колонки `rest_requests.request_tab`, `multipart_tab`, `response_tab`, в браузерной сборке — поля той же записи в `devtools.rest`. Переключение вкладки пишется тем же debounce 450 мс, что и остальные изменения запроса, поэтому запрос, открытый снова, показывает те же панели, что были открыты перед закрытием. Дублирование запроса копирует вкладки источника. Новый запрос открывается на первых вкладках панелей. Коды вкладок хранятся в нижнем регистре; запись, созданная до появления этих колонок, или значение, которого нет среди вкладок панели, читается как первая вкладка (`Headers`, `Поля`, `Response`), а не как вкладка, которой не существует.
- **Меню запроса** открывается кнопкой «...» или правой кнопкой мыши на любой строке: «Выполнить», «Копировать cURL», «Копировать cURL.exe», «Переименовать», «Дублировать», «Удалить». Кнопка «...» видна только у выбранного запроса и не появляется при наведении на остальные строки.
- **Панель запроса**: выбор HTTP-метода, URL и кнопка выполнения с вращающимся глобусом. Повторное нажатие во время выполнения прерывает запрос и показывает уведомление «Запрос прерван».
- **Вкладки запроса**: `Headers`, `Query`, `Cookies`, `Raw`. Таблицы параметров (в том числе `Form-encode`) без строки заголовков колонок: смысл колонок передают плейсхолдеры, первая строка — добавление нового параметра. Изменения в `Query` сразу перестраивают URL, изменения в `Cookies` сразу обновляют заголовок `Cookie`. Вкладка `Raw` — предпросмотр запроса (см. ниже); название вкладки одинаково короткое в обеих локалях (`Raw`), а пояснение «Необработанный запрос» / «Raw request» стоит в подсказке и в `aria-label` редактора.
- **Проверка значений по стандартам**: названия обязательно — строка таблицы с заполненным значением и пустым названием считается ошибкой, потому что на сеть она всё равно не уходит; полностью пустая строка (ни названия, ни значения) ошибкой не считается. Имена заголовков и cookie — это `token` из RFC 9110 §5.6.2 / RFC 6265 §4.1.1 (буквы, цифры и `!#$%&'*+-.^_`|~`); значения заголовков не содержат CR, LF и других управляющих символов, табуляция и пробел разрешены; значения cookie — печатные ASCII без пробела, запятой, точки с запятой, двойной кавычки, бэкслеша и управляющих символов. Параметры query проверяются в том виде, в котором они стоят в URL, по RFC 3986 §3.4: разрешены `A-Za-z0-9-._~`, sub-delims, `:` `@` `/` `?` и корректные процент-коды `%XX`; пробел, перенос строки или битый escape (`%zz`, `%2`) — ошибка. Строки `Form-encode` проверяются мягче: они автоматически кодируются при отправке, поэтому запрещены только управляющие символы, а пробелы, `&` и `=` в значениях допустимы. Названия полей и частей `Form` (multipart) — тот же `token` RFC 9110, потому что они попадают в `content-disposition` без экранирования; значения полей пишутся в тело как есть, поэтому в них запрещены только управляющие символы, а пробел, `&` и `=` допустимы. Строка файла требует названия и выбранного файла: если после перезапуска у строки осталось только имя файла, подсказка говорит выбрать файл заново, потому что байты в базе не хранятся. Пустые значения ошибкой не считаются: заголовок с пустым значением легален.
- **Как выглядит ошибка**: некорректная ячейка таблицы окрашивается в красный и получает подсказку с причиной в `title` и `aria-invalid`; новая строка из поля добавления не создаётся, пока значение не исправлено. Вкладки `Headers`, `Query`, `Cookies` и вкладка `Form-encode` показывают красную точку с текстом первой ошибки, а поле URL подсвечивается красным, если проблема в query. Вкладка `Form` — контейнер для двух таблиц, поэтому она ставит точку, когда ошибка есть хоть в одной из них, а вложенные вкладки `Поля` и `Файлы` показывают точку своей таблицы. Выполнение запроса, копирование cURL и скачивание ответа блокируются, а в уведомлениях появляется локализованная причина в формате «Запрос не отправлен: …» с названием параметра и проблемным символом (`␍`, `␊`, `␉`, `␠` или `U+XXXX`). Символы non-ASCII в значениях заголовков не запрещаются: Rust-клиент принимает те же байты, что и crate `http` (кроме DEL).
- **Пустое название**: подсказка «Название обязательно: строка без названия не отправляется. Заполните название или удалите строку.» показывается на ячейке названия. Если стереть название в существующей строке `Query` или `Cookies`, значение не теряется: URL остаётся с `?=значение`, а заголовок `Cookie` — с `=значение`, поэтому строка остаётся в таблице красной и редактируемой вместо незаметного удаления. В поле добавления строки введённое значение тоже не выбрасывается: строка не создаётся, пока название не заполнено. Полностью пустая строка удаляется из URL, из заголовка `Cookie` и не мешает выполнению запроса.
- **Body**: вкладки `JSON`, `XML`, `Text`, `Form-encode`, `Form`. Для JSON/XML доступна кнопка форматирования в панели вкладок; битая разметка и битый JSON форматируются без ошибки — отступы переставляются, текст не меняется, уведомление показывается только если в теле нет ни разметки, ни JSON-структуры. Form-encode редактируется таблицей параметров. Таблица `Form-encode` независима от текстового тела: переключение вкладок не переносит строки таблицы в тело JSON/XML/Text и не заполняет таблицу из тела. При выполнении запроса с активной вкладкой `Form-encode` тело запроса строится из таблицы (приоритет таблицы), а текстовое тело игнорируется; пустая таблица означает запрос без тела. Для тела ставится `Content-Type: application/x-www-form-urlencoded`, если заголовок не задан вручную. При импорте cURL с `application/x-www-form-urlencoded` таблица заполняется из тела импортируемого запроса, а текстовый буфер остаётся пустым.
- **Form (multipart)**: вкладка `Form` открывает две вложенные вкладки — `Поля` (таблица «имя поля / значение») и `Файлы` (таблица «имя части / файл»). В ячейке файла вместо текста показывается выбранное имя файла (при наведении — полный путь в подсказке), нажатие открывает диалог выбора: нативный в desktop и системный выбор файла в браузере. Строка добавления не создаётся, пока не выбран файл или пока название не исправлено. Строки без названия не сохраняются и не отправляются, как и в остальных таблицах. В базе хранятся только путь и имя файла, байты файла не сохраняются ни в SQLite, ни в `localStorage`, поэтому после перезапуска строка остаётся видимой, но требует повторного выбора файла. В браузерной сборке выбранный `File` живёт только в текущей сессии: после перезагрузки страницы тело multipart собрать не из чего, и запрос завершается уведомлением о недоступном файле.
  При выполнении запроса с активной вкладкой `Form` тело кодируется вручную: parts идут в порядке таблиц (сначала поля, затем файлы), boundary — UUID, который генерируется кодирующим модулем на каждый запрос. `Content-Type: multipart/form-data; boundary=…` всегда ставится вместо вручную введённого `Content-Type`, потому что boundary знает только кодирующий модуль. Тип содержимого части определяется по расширению файла (`application/octet-stream` для неизвестного), имя файла с символами вне ASCII уходит в `filename*=UTF-8''…` наряду с очищенным `filename`. Для вкладки `Form` в cURL-экспорт идут `--form name="значение"` и `--form name=@"путь"` (с `;filename=` только если имя отличается от имени файла), а `--data-raw` не появляется.
- **Ответ**: вкладки `Response`, `Headers`, `Raw`. Верхняя панель показывает статус, размер (`bytes`/`KiB`/`MiB`) и время (`ms`/`sec` с двумя знаками), а также кнопки форматирования/деэкранирования для XML/JSON (битый XML и битый JSON форматируются без ошибки, обычный текст — нет), предпросмотра HTML, скачивания вложения и копирования тела. Тело на вкладке `Response` подсвечивается по типу содержимого: JSON и XML — своими языками, HTML — языком HTML (`text/html`, `application/xhtml+xml`, `application/xhtml`, `text/x-html`, `application/…+html`, а также ответ без `Content-Type`, но с тегом `<html>` или с `<!DOCTYPE html>` в начале), остальные типы — без подсветки. XHTML читается именно HTML-языком, а не XML, и содержимое тегов `<script>` и `<style>` подсвечивается как JS и CSS. Предпросмотр HTML остаётся отдельной кнопкой и по-прежнему отдаёт iframe; вкладка `Raw` всегда показывает обычный текст без подсветки, потому что это байты как полученные.
- **Сохранение ответа**: чекбокс `Save` доступен только для текстовых ответов и сохраняется вместе с запросом. Ответ, заголовки ответа, отправленный запрос и строка статуса ответа восстанавливаются при следующем открытии запроса.
- **Вложения и бинарные ответы**: при `Content-Disposition: attachment` тело не загружается заранее; показывается кнопка скачивания. Двоичные ответы также не рендерятся в редакторе.
- **Raw (запрос)**: вкладка в панели запроса после `Cookies`; в обеих локалях она называется `Raw`, а подсказка и `aria-label` редактора говорят, что это именно необработанный запрос. Показывает запрос, который уходит в сеть сейчас, или тот дамп, что сохранил бэкенд после последнего выполнения; кнопки копируют его как `cURL` для POSIX и как `cURL.exe` для Windows. Для вкладки `Form` предпросмотр показывает части с boundary и меткой `<bytes of путь>` вместо содержимого файла, а `Content-Length` равен длине предпросмотра: реальный запрос получает длину уже закодированного тела с настоящими байтами. Windows-команда экранируется для cmd.exe: каждый аргумент в обычных двойных кавычках (`"…"`), внутренние кавычки как `\"`, бэкслеши удваиваются, перенос строки в теле сворачивается в пробел, URL стоит сразу после `curl.exe` (первая строка), а каждая строка (кроме последней) заканчивается на ` ^`, чтобы многострочная команда выполнилась одной командой в cmd.exe. Процент не удваивается: интерактивный cmd.exe передаёт `%` как есть, но при сохранении команды в `.bat`-файл проценты нужно удвоить вручную (`%%`), иначе батч подставит переменные.
- **Raw (ответ)**: вкладка в панели ответа после `Headers`, тоже `Raw` в обеих локалях с подсказкой «Необработанный ответ» / «Raw response». Дамп построен по проводному формату: первая строка — строка статуса, которую ответил сервер (`HTTP/1.1 200 OK`, версия берётся из фактического протокола ответа), затем по одному заголовку на строку, пустая строка и тело ровно в тех байтах, в которых оно пришло — без форматирования и без деэкранирования, поэтому оно совпадает с телом на вкладке `Response` до нажатия «Format» и с `Raw` после форматирования. Над дампом показаны статус и размер, кнопка копирует дамп целиком. Для вложения и бинарного ответа дамп содержит строку статуса и заголовки без тела — байты в редактор не загружаются. У ответа из браузерной сборки первая строка всегда `HTTP/1.1 …`: `fetch` не сообщает версию протокола. Дамп собирается и из сохранёного ответа, поэтому после перезапуска приложения вкладка показывает те же байты без нового вызова; у ответа, сохранённого до появления строки статуса, первая строка просто отсутствует — дамп показывает то, что сохранилось.
- **Импорт cURL**: команда разбирается с учётом shell-кавычек. Одинарные кавычки не экранируются вовсе (кавычка внутри делается приёмом `'\''`), в двойных бэкслеш снимается только перед `$`, `` ` ``, `"`, `\` и переносом строки, а bash ANSI-C кавычки `$'…'` — формат «Copy as cURL (bash)» в браузерах — разворачивают `\n`, `\r`, `\t`, `\\`, `\'`, `\"`, `\xHH` и `\uHHHH` всегда. Пустая кавычка (`''`) остаётся отдельным аргументом и не сдвигает следующие за ней. Импорт распознаёт cmd.exe-формат браузера («Copy as cURL (cmd)»): аргументы в `^"…^"`, каждый специальный символ экранирован каретой (`^$`, `^|`, `^(`, `^\^"` для кавычки внутри аргумента), `%` удвоен, а перенос строки записан как `^` перед CR. Кареты снимаются, `%%` сворачивается обратно в `%`, а настоящие переносы внутри аргумента сохраняются: без этого тело формы осталось бы одной строкой. Команда без кареты перед кавычкой считается POSIX или обычным `curl.exe`-форматом — там кареты у переносов строк убираются, а кареты внутри значений остаются текстом. Тело запроса дополнительно деэкранируется: экспортеры часто ставят `\"` и `\n` внутри обычных кавычек, где shell передал бы бэкслешы буквально, и в буфере остаётся текст с escape-последовательностями вместо разметки. Деэкранирование срабатывает, когда тело становится корректным JSON или XML только после разворота, или когда в теле нет настоящих переносов строк, а `\n` их заменяют. Тело, которое и так читается как валидный JSON/XML (например, значение `"line1\nline2"`, где бэкслеш — часть строки), и тело с настоящими переносами строк остаются без изменений; `Form-encode` не деэкранируется, потому что строки таблицы не хранят управляющие символы. Тип тела берётся из `Content-Type`, а если заголовка нет — определяется по телу уже после деэкранирования. Параметры `--form`, `-F` и `--form-string` создают запрос с вкладкой `Form`: значение без `@` идёт в таблицу `Поля`, а `@путь` (в том числе с `;filename=` и `;type=` в любом порядке) — в таблицу `Файлы`, где `;filename=` становится именем части; `;type=` не сохраняется, тип части определяется по расширению файла. `--form-string` остаётся полем, даже если значение начинается с `@`, потому что этот флаг не читает файлы. Тело `multipart/form-data`, которое браузер записал в `--data-raw`, тоже разбирается на части: boundary берётся из `Content-Type`, а без заголовка — из первой строки тела; части с `name=` идут в таблицу `Поля` с их значениями, части с `filename=` — в таблицу `Файлы` без пути, потому что байты файла в команду не попадают, и такая строка подсвечивается и блокирует отправку, пока файл не выбран. Значит вкладка `Form` создаётся и из `--data-raw`, а не только из `--form`. В cmd.exe-формате браузера тело формы часто стоит не в аргументе, а после пустого `--data-raw "^"`: дамп написан отдельными строками с отступом как у аргументов, и каждая строка закрыта каретой, которая присоединяет следующую. Такие строки собираются обратно в тело, иначе строка границы начинается с `-` и читается как неизвестный флаг; пустой аргумент — единственный признак этого места, поэтому тело, которое действительно помещается в один аргумент, не теряется. `Content-Type: multipart/form-data; boundary=…` из импортированной команды убирается из таблицы заголовков: boundary генерирует кодирующий модуль. Флаг `-d` рядом с `-F` считается ещё одним полем того же multipart-тела.
- **Разделители**: перетаскиваемые вертикальные разделители между проводником и правой областью и между конфигурацией запроса и ответом, а также горизонтальный разделитель между параметрами и телом.

Критерии проверки: запрос с именем заголовка `Content Type`, значением заголовка с переводом строки, query-параметром с пробелом или битым `%zz` не уходит в сеть и показывает локализованную причину; значения `X-Custom_1`, `application/json; charset=utf-8`, `q=hello%20world` и строки формы `user name` / `a b & c` проходят без подсветки; строка `Form-encode` с переводом строки блокирует выполнение только при активной вкладке `Form-encode`; строка с заполненным значением и пустым названием блокирует выполнение и подсвечивает ячейку названия, а полностью пустая строка — не блокирует. В таблице `Поля` имя `bad name` подсвечивается, а `upload_file` и значение `a b&c=d` проходят; значение поля с переводом строки подсвечивается, потому что в multipart оно пишется без кодирования. Строка файла, у которой остался только `filename` без выбранного файла, подсвечивается и блокирует выполнение, копирование cURL и скачивание ответа; после повторного выбора файла тот же запрос уходит в сеть. Тело `Form` не трогает буфер JSON/XML/Text и таблицу `Form-encode` при переключении вкладок, обе таблицы переживают перезапуск (файл — как путь и имя), а дублирование запроса копирует обе таблицы. Экспорт запроса с вкладкой `Form` отдаёт `--form`-части и `--form name=@"путь"` без `--data-raw`, без вручную поставленного `Content-Type` и без частей, у которых нет пути; повторный импорт этой команды возвращает те же поля, те же файлы с алиасом и те же заголовки. Импорт команды с `-F 'doc=@/tmp/a.pdf;filename=alias.pdf;type=application/pdf'` создаёт вкладку `Form` с таблицей файлов и убирает из заголовков импортрованный boundary. Импорт команды браузера, где тело `multipart/form-data` записано в `--data-raw`, создаёт вкладку `Form` со всеми полями дампа — включая части с пустым значением и с кириллицей — и оставляет текстовый буфер пустым; импорт cmd.exe-команды с карет-экранированием даёт тот же результат с чистыми URL, заголовками и cookie без каретов, а `%%` в значениях сворачивается в `%`; cmd.exe-команда, где браузер записал тело после пустого `--data-raw "^"` отдельными строками с отступом, импортируется с теми же полями и строкой `Файлы`, чистыми заголовками и без каретов, а значения полей не подсвечиваются. Часть дампа с `filename=` создаёт строку `Файлы` без выбранного файла: она подсвечивается и блокирует отправку, пока файл не выбран. Тело, которое только упоминает `Content-Disposition: form-data` и не имеет границы, остаётся текстом. Импорт команды, где тело в одинарных кавычках содержит `\"` и `\n`, создаёт запрос с деэкранированным XML-телом, которое форматируется кнопкой без ошибки; импорт `$'…'`-команды браузера даёт тело с настоящими переносами строк; JSON-тело со значением `"line1\nline2"` импортируется без изменений, а `application/x-www-form-urlencoded` тело заполняет таблицу `Form-encode` и оставляет текстовый буфер пустым. Выбор проекта и запроса переживает перезапуск: после закрытия и повторного запуска открыты те же проект и запрос; если выбранный запрос удалить, а затем перезапустить приложение, открывается первый запрос того же проекта. Тело или ответ с незакрытым тегом и тело с текстом перед `<?xml?>` форматируются кнопкой без ошибки; ответ без разметки в режиме JSON или XML по-прежнему получает уведомление об ошибке. Вкладка `Raw` стоит в панели запроса после `Cookies` и в панели ответа после `Headers`, в обеих локалях с названием `Raw`; кнопки `cURL (Posix)` и `cURL (Windows)` работают с вкладки запроса, а при ошибке проверки запроса не копируют команду и показывают ту же причину, что и при выполнении. Дамп ответа начинается со строки статуса, затем идут заголовки, пустая строка и тело как полученные: форматирование тела на вкладке `Response` меняет только её, а `Raw` остаётся исходным байтом; дамп сохранённого ответа показывается после перезапуска приложения без нового вызова, снятие чекбокса `Save` убирает и тело, и строку статуса. Вложение и бинарный ответ показывают в `Raw` строку статуса и заголовки без тела. Ответ с `Content-Type: application/xhtml+xml`, `application/xhtml` или `text/x-html`, а также HTML-документ без `Content-Type` (`<!DOCTYPE html>` или тег `<html>` в начале тела) подсвечивается на вкладке `Response` как HTML, `application/atom+xml` остаётся подсветкой XML, а `Raw` у такого ответа остаётся обычным текстом; кнопка предпросмотра HTML по-прежнему открывает iframe вместо редактора. Открытые вкладки переживают перезапуск: запрос, у которого были открыты `Raw` запроса, `Файлы` и `Raw` ответа, после перезапуска открывается на этих вкладках, дубликат — на тех же, что у источника, а запрос, сохранённый до появления этих колонок, — на `Headers`, `Поля` и `Response`.

В desktop-сборке запрос выполняет Rust-бэкенд, поэтому CORS не ограничивает клиент. В браузере используется `fetch` с ограничениями браузера: часть заголовков недоступна, а ответы подчиняются CORS. В браузере данные запросов сохраняются в `localStorage` под ключом `devtools.rest`.

Ограничения клиента: таймаут запроса — 120 секунд, поддерживаются HTTP и HTTPS, редиректы ограничены 10 переходами. Запросы, тела и сохранённые ответы хранятся в базе приложения и не синхронизируются между устройствами. Строка статуса ответа хранится рядом с ответом, но у ответов, сохранённых до её появления, она не восстановима: `Raw` показывает такие ответы без первой строки. У браузерной сборки первая строка всегда `HTTP/1.1 …`, потому что `fetch` не отдаёт версию протокола. У запросов, сохранённых до разделения вкладок тела, в текстовом буфере может оставаться закодированная строка Form-encode: при активной вкладке `Form-encode` она не отправляется, приоритет у таблицы. Вкладка `Form` хранит пути файлов, а не их содержимое: если файл перемещён, переименован или доступен только на другом устройстве, часть нужно выбрать заново, и предпросмотр отправленного запроса показывает метку `<bytes of путь>` вместо байтов. В браузере содержимое выбранного файла живёт только до перезагрузки страницы, а тип содержимого части определяется по разным таблицам расширений (в desktop — по `mime_guess`, в браузере — по встроенному списку), поэтому для редких расширений тип может отличаться; оба клиента возвращают `application/octet-stream`, если расширение неизвестно.

### WSDL-клиент

Страница `/wsdl` импортирует файлы WSDL 1.1 и выполняет SOAP-запросы. Она доступна только в desktop-сборке: в браузере вместо интерфейса показывается карточка «WSDL-клиент доступен в desktop-версии», а Tauri-команды в браузерной сборке не вызываются вовсе.

- **Проводник** слева: выпадающий список проектов (`Не выбран` показывает все файлы) с кнопкой «...» и меню «Создать проект», «Переименовать проект», «Удалить проект» — две последние строки недоступны, если проект не выбран; создание и переименование открывают поле ввода вместо списка, `Enter` подтверждает, `Escape` отменяет. Ниже — кнопка импорта с кнопкой «?» рядом и дерево `файл → служба → операция`. Имя строки файла — последний сегмент его URL (или хост, если URL заканчивается на `/`), а в подсказке — полный адрес. Строки раскрываются шевроном; ветка с выбранной операцией раскрывается сама, но ручное раскрытие строки сильнее авто-раскрытия. Выбранная операция подсвечена левой акцентной полосой, при наведении строка получает нейтральный фон. Клик по строке файла раскрывает его службы, клик по строке службы — его операции, клик по операции открывает её запрос. Кнопка «...» показывается только у файла, в котором лежит выбранная операция (правый клик открывает то же меню на любой строке): «Выполнить» и «Удалить». Удаление требует подтверждения прямо в меню («Удалить „имя“ со службами, операциями и ответами?») и убирает файл со службами, операциями, адресами и состояниями запросов; «Выполнить» запускает выбранную в этом файле операцию, а если выбрана операция другого файла — первую операцию этого файла. Удаление проекта убирает и его файлы.
- **Фильтр операций** — поле под кнопкой импорта: совпадение по подстроке имени операции без учёта регистра и без учёта пробелов по краям. Остаются только те операции, в имени которых есть введённый текст, а вместе с ними — их службы и файлы; служба и файл без подходящей операции из списка исчезают. Подходящие ветки раскрыты всегда, поэтому строки видно без кликов по шеврону, а ручные раскрытия при этом не меняются: после очистки поля дерево возвращается к тем же раскрытиям. Крестик в поле и `Escape` очищают фильтр, при пустом поле показано всё дерево. Если ни одна операция не подходит, вместо дерева — «Ни одна операция не подходит под фильтр». Фильтр ничего не сохраняет и не меняет выбор: запрос выбранной операции остаётся открытым в правой панели, а когда выбранная операция скрыта фильтром, кнопка «...» не появляется ни у одной строки.
- **Импорт** читает адрес из буфера обмена (`clipboard-manager`) по кнопке «Импортировать WSDL из буфера обмена». Во время выгрузки кнопка превращается в «Отменить импорт», и отмена даёт уведомление «Импорт отменён». Кнопка «?» открывает справку о том, как работает импорт. Пустой буфер и буфер без `http`/`https` адреса дают уведомление с тем, что в буфере сейчас лежит; выгрузка с кодом 4xx/5xx, таймаут 30 с, файл больше 5 МБ, битый XML, документ не-WSDL, WSDL 2.0 и документ без единой SOAP-операции дают локализованную причину и не создают запись в базе. Импорт идёт в выбранный проект (без выбора — в «Не выбран»), а проводник переходит в проект, куда лёг файл, чтобы новая строка была видна.
- **Повторный импорт** того же адреса в тот же проект обновляет дерево, службы, операции, адреса и шаблоны, но сохраняет `id` операций и их состояние — сохранённое тело, выбранный адрес и заголовки не теряются. В том же проекте другой URL создаёт отдельную строку дерева; импорт того же адреса в другой проект — новая строка со своим состоянием.
- **Предупреждения импорта** — часть импорта, а не ошибка: внешние `xsd:import`/`xsd:include` не выгружаются, у порта может не быть SOAP-привязки или `soap:address`, привязка может не ссылаться на `portType`, у операции — входного элемента, рекурсивный тип и тип, который не удалось разрешить, обрезаются. Каждый случай — код в списке предупреждений файла: строка файла получает знак «!» со списком в подсказке, а полный список показывается баннером над панелью запроса. Импорт с предупреждениями завершается успешно.
- **Правая панель** выбранной операции: имя операции, служба и версия SOAP (`1.1`/`1.2`) — версия берётся из выбранного адреса, потому что одна и та же операция может быть привязана через порты разных версий, — выпадающий список всех `soap:address location` этой операции, растянутый на всю свободную ширину строки (имя операции и служба сокращаются до `220px`), и кнопка-глобус. Повторное нажатие во время выполнения прерывает запрос и показывает «Запрос прерван»; если у операции нет ни одного адреса, запуск блокируется уведомлением «Адрес не выбран».
- **Шаблон запроса** генерируется по XSD-схеме импортного файла: `element`, `complexType`, `simpleType`, `sequence`, `all`, `choice`, `complexContent`/`simpleContent` с `extension` и `restriction`, `attribute`, `ref`, `minOccurs`/`maxOccurs`, `elementFormDefault`. Атрибут `nillable` схема читает, но он ничего не меняет: такой элемент печатается как обычный. Наследование применяется целиком: базовый тип отдаёт свои поля первыми, а после них идут элементы и атрибуты, которые объявляет само производное, — шаблон обёртки над базовым запросом содержит и реквизиты базы, и тело, добавленное производным. `restriction` показывает поля базы целиком (лишнее пользователь убирает сам), а `simpleContent` с атрибутами печатает `?` внутри тега рядом с его атрибутами. Производный тип разворачивается от базы, поэтому при достижении предела элемента в шаблоне остаются поля базы, а не только глубокое собственное содержимое. Значение каждого листа, атрибута и текста — `?`, как в SoapUI: правдоподобные образцы (`text`, `0`, `2026-01-01`) не подставляются, и пользователь либо заменяет `?` своими данными, либо убирает тег. Элемент с `minOccurs="0"` остаётся в шаблоне открытым, а над ним стоит метка `<!--Optional:-->` — он не закомментирован. Элемент с `maxOccurs="unbounded"` печатается один раз под меткой `<!--Zero or more repetitions:-->`, а при непустом `minOccurs` — под `<!--One or more repetitions:-->`, чтобы блок скопировали столько раз, сколько нужно; конечный `maxOccurs` печатает две копии без метки. Все атрибуты печатаются прямо в теге как `имя="?"` — лишний атрибут убирается вместе с тегом, отдельных подсказок про необязательные атрибуты нет. Ветки `choice` печатаются закомментированными вариантами, каждый со своей меткой `<!--Choice:-->`, неразрешённый тип или цикл — комментарием с его именем. Подсказка про `xsi:nil="true"` не печатается: метка `Optional:` уже говорит, что элемент можно не заполнять. Каждая строка шаблона содержит не более одного комментария: метка дочернего элемента, который ветка `choice` уже закомментировала, печатается одной парой маркеров и сохраняет запись SoapUI — `<!--Optional:-->`, а не `<!-- Optional: -->`; вложенных `<!-- <!-- … --> -->` и обрезанных `<!- - … - ->` в шаблоне не бывает, а закомментированный блок сохраняет отступы схемы: снятие комментариев возвращает вложенную структуру. Глубина вложенности ограничена 32 уровнями, число элементов — 2000, при достижении предела шаблон обрывается и файл получает предупреждение. Ни один из этих случаев не роняет импорт.
- **Тело запроса** редактируется в CodeMirror (XML) и предзаполняется шаблоном; правки сохраняются в SQLite с задержкой 450 мс вместе с выбранным адресом и строками заголовков пользователя, поэтому при повторном открытии операции остаётся то, что ввёл пользователь, а не шаблон. В панели вкладок есть кнопка форматирования (битый XML форматируется без ошибки, текст с разметкой не меняется) и кнопка «Восстановить сгенерированный шаблон», недоступная, если у операции нет входного элемента. При повторном импорте пересобирается шаблон в строке операции, а сохранённое тело, выбранный адрес и заголовки не меняются.
- **Вкладки запроса** — `XML`, `Headers`, `Raw`. В `Headers` незаменяемые строки привязки идут первыми: их ячейки только для чтения, без кнопки удаления и с подсказкой «Этот заголовок пишет SOAP-привязка, в редакторе он недоступен». Обязательные строки не проверяются и не сохраняются: в SQLite уходят только строки пользователя, а обязательные пересчитываются при каждом открытии операции и каждой отправке. Строки пользователя проверяются по тем же правилам RFC, что и в Rest client: неверная ячейка краснеет и получает причину в подсказке, вкладка `Headers` показывает красную точку с текстом первой ошибки, а выполнение запроса и скачивание ответа блокируются уведомлением «Запрос не отправлен: …». `Raw` — read-only предпросмотр обмена: до первого вызова он показывает конверт и заголовки, которые ушли бы сейчас, а после вызова — тот дамп, что записал бэкенд; кнопка копирует текст, cURL из этой страницы не экспортится. Пустое тело не уходит в сеть, если у операции есть непустой шаблон, — запуск даёт «Перед выполнением запроса заполните тело»; операция без входного элемента отправляет пустое Body намеренно.
- **Отправка**: тело оборачивается в SOAP-конверт выбранной версии и уходит `POST` через Rust-бэкенд Rest client, поэтому CORS не мешает. Заголовки задаёт приложение: SOAP 1.1 — `Content-Type: text/xml; charset=utf-8` и `SOAPAction: "<действие>"`, SOAP 1.2 — `Content-Type: application/soap+xml; charset=utf-8; action="<действие>"`. Набор пересчитывается по версии и `soapAction` выбранного адреса на каждой отправке, поэтому дубликат `Content-Type` или `SOAPAction`, введённый вручную, в запрос не попадает: строка пользователя с таким же именем (в любом регистре и с пробелами по краям) убирается из таблицы, из базы и с сети. Те же обязательные строки показываются в таблице `Headers` первыми, только для чтения.
- **Ответ**: вкладки `XML`, `Headers`, `Raw`. Панель над телом показывает статус, размер (`bytes`/`KiB`/`MiB`) и время (`ms`/`sec`), чекбокс `Save` и кнопки: форматирование и деэкранирование для XML/JSON-ответов (битый XML и битый JSON форматируются без ошибки — отступы переставляются, текст не меняется; обычный текст остаётся с уведомлением), копирование тела и скачивание для вложения или бинарного ответа. Тело лежит в read-only CodeMirror с подсветкой по типу содержимого — XML, JSON и HTML по тем же правилам, что и в Rest client (любой подтип содержимого с `html`, включая `application/xhtml+xml`, и HTML-документ без заголовка); бинарный ответ и `Content-Disposition: attachment` в редактор не загружаются — показывается карточка с кнопкой скачивания и именем файла из `Content-Disposition` (форма `filename*=UTF-8''…` сильнее обычной `filename=`), очищенным до одного безопасного имени. `Headers` — таблица заголовков ответа, а если их нет — «Заголовков ответа нет»; `Raw` — весь обмен целиком: строка статуса, которую ответил сервер, по одному заголовку на строку, пустая строка и тело ровно в тех байтах, в которых оно пришло. Если содержимое ответа — XML (`text/xml`, `application/soap+xml` и любой другой XML-тип), дамп подсвечивается как XML и над редактором появляется кнопка `Format`: она переставляет отступы только в теле, а строка статуса и блок заголовков остаются нетронутыми, поэтому обрамление обмена не меняется; сохранённые байты и вкладка `XML` при этом не меняются, уведомление об ошибке появляется только для тела без разметки. Для остальных типов дамп остаётся обычным текстом без кнопки `Format`, и копируется целиком. HTTP 500 с `soap:Fault` показывается как ответ со статусом 500 и XML-телом, а не как сетевая ошибка. Скачивание повторяет тот же SOAP-вызов через Rust-бэкенд и пишет ответ в выбранный файл; в браузерной сборке оно недоступно, потому что страница desktop-only.
- **Сохранение ответа**: чекбокс `Save` доступен для текстовых ответов и хранится в состоянии операции. Когда он включён, ответ, заголовки ответа, строка статуса и отправленный запрос записываются в SQLite сразу после выполнения и показываются при следующем открытии операции — тело в том виде, как оно пришло, а `Raw` собирает из них тот же обмен целиком, без нового вызова. Выключение чекбокса убирает сохранённый ответ, его заголовки и строку статуса, тело текущего вызова остаётся на экране; правки тела запроса при этом не затрагивают сохранённый ответ, и наоборот. У ответа, сохранённого до появления строки статуса, первая строка просто отсутствует — дамп показывает то, что сохранилось.
- **Восстановление выбора**: выбранные проект и операция сохраняются в SQLite (`app_settings`, ключи `wsdl.activeProject` и `wsdl.activeOperation`; пустая строка означает «ничего не выбрано»). После запуска открыты тот же проект и та же операция; если сохранённая операция принадлежит другому проекту, проводник переходит в тот проект; если операция удалена — выбирается первая операция видимого списка; если удалён проект — открывается «Не выбран» со всеми файлами.
- **Разделители**: перетаскиваемый вертикальный разделитель между проводником и правой областью и горизонтальный разделитель между запросом и ответом.

Критерии проверки: пункт `WSDL` в верхней панели подсвечивается на `/wsdl`; проект создаётся, переименовывается и удаляется вместе с его файлами; импорт адреса из буфера создаёт строку дерева со службами и операциями, а выбор операции показывает её адреса и шаблон, построенный по схеме; битый XML, `404`, адрес без схемы, не-WSDL документ, WSDL 2.0 и документ без операций дают локализованный тост и не создают запись; повторный импорт того же адреса оставляет изменённое тело и выбранный адрес; выбор операции переживает перезапуск приложения; поле фильтра оставляет только операции, в имени которых есть введённая подстрока, и их файлы, подходящие ветки раскрыты без кликов по шеврону, а ручное раскрытие переживает очистку фильтра; крестик и `Escape` сбрасывают фильтр, а при отсутствии совпадений вместо дерева показывается «Ни одна операция не подходит под фильтр»; удаление файла требует подтверждения и убирает его службы, операции, адреса и состояния; `soap:Fault` с HTTP 500 показывается в панели ответа со статусом 500; отмена запроса даёт уведомление; в браузерной сборке показывается заглушка, и страница не падает из-за отсутствия Tauri. Строки `Content-Type` и `SOAPAction` в таблице `Headers` только для чтения, без кнопки удаления и не сохраняются: после перезапуска в таблице остаётся ровно одна пара обязательных строк и строки пользователя, а имя `Content - Type` или `soapaction` в другом регистре убирается из таблицы. Заголовок с именем `bad header` подсвечивается красным, ставит точку на вкладке `Headers` и блокирует выполнение и скачивание с локализованной причиной; значение с переводом строки блокируется как управляющий символ, а значение с пробелом проходит. Предпросмотр `Raw` до первого вызова показывает тот же конверт и те же заголовки, что уходят в сеть, и копируется кнопкой; после вызова там лежит дамп бэкенда. Чекбокс `Save` записывает ответ, и после перезапуска приложение без нового вызова показывает тело, заголовки и тот же дамп `Raw` со строкой статуса; снятие чекбокса убирает сохранённый ответ и строку статуса, не трогая тело запроса, и правки тела не трогают сохранённый ответ. Операция с непустым шаблоном и пустым телом не отправляется с уведомлением «Перед выполнением запроса заполните тело», а операция без входного элемента уходит с пустым Body. Форматирование ответа переставляет отступы XML и битого XML без ошибки и не меняет текст, копирование отдаёт текст до форматирования, а `Raw` ответа после `Format` сохраняет строку статуса и заголовки нетронутыми, а ответ без XML-типа показывает `Raw` обычным текстом и без кнопки `Format`; бинарный ответ и `attachment` дают карточку с кнопкой скачивания и именем из `Content-Disposition`. Шаблон операции, где `minOccurs="0"` вложен в `minOccurs="0"` и в ветку `choice` (элементы при этом помечены `nillable="true"`), печатает все элементы открытыми под меткой `<!--Optional:-->` и `?` вместо значений: ни `<!-- <!-- … --> -->`, ни `<!-- Optional: -->`, ни обрезанных `<!- - … - ->` в нём не встречается, пустых комментариев тоже нет, а строки закомментированной ветки `choice` сохраняют отступ; комментария про `xsi:nil` в шаблоне нет ни у одного элемента. Элемент с `maxOccurs="unbounded"` печатается один раз под меткой `<!--Zero or more repetitions:-->` (или `<!--One or more repetitions:-->` при `minOccurs="1"`), элемент с `maxOccurs="3"` — дважды без метки, а атрибуты стоят внутри тега как `имя="?"` — ни одного правдоподобного образца вроде `text` или `2026-01-01` в шаблоне нет.

Ограничения: поддерживается только WSDL 1.1 с привязками SOAP 1.1 и SOAP 1.2 — WSDL 2.0, HTTP/XML-привязки и MIME-привязки отклоняются или помечаются предупреждением. Внешние `xsd:import`/`xsd:include` не выгружаются, поэтому типы из чужих пространств имён остаются в шаблоне комментарием. Шаблон — отправная точка, а не валидатор: приложение не проверяет заполненное тело по схеме и не чинит его. Ответ сохраняется только при включённом чекбоксе `Save` и только текстовый; вложения и бинарные ответы в базе не лежат. Из страницы WSDL нельзя экспортить вызов как cURL: вкладка `Raw` показывает обмен и копирует его текстом. Файл выгружается целиком в память с лимитом 5 МБ и таймаутом 30 с, XML разбирается без внешних сущностей. Данные WSDL лежат в базе приложения и не синхронизируются между устройствами.

### Глобальные переменные

Страница `/global-vars` задаёт именованные значения, которые desktop-приложение подставляет в запросы Rest client и WSDL-клиента как `{{ name }}`. В браузерной сборке вместо интерфейса показывается карточка «Глобальные переменные доступны в desktop-версии», и ни одна команда не вызывается.

- **Строки переменных**: кнопка типа (замок — безопасная, открытый замок — обычная), имя, значение, кнопка копирования шаблона `{{ name }}` и кнопка удаления. Ниже списка — строка добавления: тип, имя, значение и «Добавить переменную». Список отсортирован по имени без учёта регистра.
- **Имя** — латинские буквы, цифры и подчёркивание, первый символ — буква или подчёркивание, не более 64 символов; пробелы по краям снимаются. Имена уникальны без учёта регистра: `Token` и `token` — одна переменная. Недопустимое или занятое имя подсвечивается красным, причина лежит в подсказке, и ни одна запись не делается. Если имя заняли между проверкой на экране и записью, бэкенд отвечает той же причиной («Переменная „name“ уже есть»), и она показывается локализованно.
- **Тип значения**: обычное значение живёт в SQLite, безопасное — в системном хранилище секретов (Credential Manager в Windows, Keychain в macOS, Secret Service поверх D-Bus в Linux) под service `app.webdev.usefultools.global-vars`, где аккаунт — `id` переменной, поэтому переименование не трогает секрет. В Linux нужен работающий провайдер Secret Service (GNOME Keyring или KWallet): без него хранилище отвечает, что записи нет. Обычная переменная становится безопасной сразу: её значение переносится в хранилище, а колонка очищается. Перевод безопасной в обычную требует подтверждения («Перенести значение в базу данных»), потому что секрет сознательно выходит из хранилища, после чего запись в нём удаляется.
- **Очередь записей**: правки имени и значения уходят в базу через 450 мс. Перевод строки в другой тип и подтверждение «Перенести значение в базу данных» сначала записывают ожидающее изменение и только потом меняют тип, поэтому значение, набранное за мгновение до клика, не теряется; удаление строки отменяет незаписанную правку.
- **Без сохранённого значения**: у безопасной строки, у которой в хранилище ничего нет, вместо `••••••` показывается «Значение ещё не сохранено» — точки обещали бы секрет, которого нет. Раскрытие такой строки отвечает пустотой, и поле можно заполнить.
- **Отказ хранилища отделён от пустой записи**: «Не удалось обратиться к хранилищу секретов: …» означает, что хранилище недоступно, а «Значение „name“ отсутствует в хранилище секретов…» — что записи нет; вторая причина говорит ввести значение заново и объясняет требование GNOME Keyring/KWallet в Linux. При отказе хранилища введённый текст остаётся на экране, чтобы его можно было повторить, а секрет в хранилище не меняется.
- **Просмотр безопасного значения**: строка показывает `••••••` и глаз. По нажатию значение достаётся из хранилища и открыто 15 с; в это время его можно редактировать, и новое значение пишется в хранилище тем же debounce, что и переименование (450 мс). 15 с — жёсткий срок: если текст набрали в последние 450 мс, истечение срока сначала записывает его в хранилище и только потом скрывает поле. Крестик скрывает значение раньше, скрытие ничего не пишет. Список переменных секретов не содержит: у безопасной строки значение приходит как `null`, и достать его можно только кнопкой раскрытия.
- **Где подставляется**: значения query-параметров (в URL шаблон хранится как `%7B%7Bname%7D%7D`, бэкенд раскрывает его перед отправкой), значения заголовков, тело JSON/XML/Text, значения таблицы `Form-encode` и значения полей вкладки `Form`. Буфер тела читается только тогда, когда на выбранной вкладке он и уходит в сеть: для `Form-encode` и `Form` в запрос идут таблицы, поэтому оставшийся от другой вкладки буфер с шаблоном не блокирует отправку. Не подставляются хост, порт и путь URL, имена query-параметров, имена заголовков, имена и пути частей multipart — такой шаблон не уходит в сеть, а запрос блокируется с причиной «„{{ name }}“ — место, где переменная не подставляется». Браузерная сборка отказывает в том же, в чём отказывает desktop: сканер читает URL целиком (хост, путь, имена и значения параметров в percent-коде), имена заголовков и только тот буфер, который выбран.
- **Значение с управляющим символом**: если подставленное значение заголовка или поля `Form` содержит CR или LF (HTAB разрешён), запрос блокируется уже после подстановки с причиной «Значение {field} не может содержать управляющий символ {char}». Проверка видит только бэкенд, потому что имя переменной само по себе корректно, а её значение пришло из хранилища или базы.
- **Неизвестное имя** блокирует выполнение с уведомлением «Неизвестная переменная: …». Рекурсии нет: значение, которое само содержит `{{other}}`, отправляется как текст. Подстановка делается на Rust-бэкенде перед отправкой, а в дампе `Raw` отправленного запроса (и в сохранённом дампе) безопасные значения показываются как `********` — настоящие байты в SQLite не попадают. Дамп строится из маскированной версии запроса, поэтому `Content-Length` в нём описывает сам дамп: длина настоящего значения нигде не сохраняется. Вкладка `Raw` запроса показывает подсказку о том, что переменные подставляются при отправке, а безопасные значения в ней скрыты.
- **cURL**: запрос с шаблонами нельзя ни скопировать, ни экспортировать — уведомление объясняет, что cURL не имеет доступа к хранилищу секретов. В браузерной сборке такой запрос не отправляется вообще.
- **Удаление** требует подтверждения прямо в строке («Удалить „name“ и её сохранённое значение?») и убирает вместе с записью её секрет из хранилища.

Критерии проверки: в desktop-сборке созданная безопасная переменная `token` подставляется в query, заголовок и тело запроса, а вкладка `Raw` и сохранённый дамп отправленного запроса показывают `********` вместо значения, и `Content-Length` в этом дампе равен длине дампа, а не настоящих байтов; запрос с неизвестным шаблоном не уходит в сеть и называет переменную; `{{ token }}` в пути URL, в имени параметра или в имени заголовка блокируется с той же причиной, и в браузерной сборке такой запрос тоже не отправляется; буфер с `{{ id }}` на вкладке `Form-encode` не блокирует запрос, потому что в сеть идут таблицы; значение переменной с символом переноса строки блокирует запрос и называет поле и символ; имя `bad name` подсвечивается и не создаёт запись, а `Token` при уже существующем `token` — тоже; раскрытое безопасное значение исчезает через 15 с, набранное в последние 450 мс значение при этом сначала попадает в хранилище, крестик скрывает его раньше без записи; безопасная переменная без секрета показывает «Значение ещё не сохранено» вместо точек; перевод строки в безопасный тип записывает значение, набранное за мгновение до клика; удаление спрашивает подтверждение и только после второго клика убирает строку, отменяя незаписанную правку; в браузерной сборке нет ни поля ввода, ни кнопки добавления.

Ограничения: переменные глобальные — они не привязаны к проекту или запросу и не синхронизируются между устройствами. Безопасное значение не может быть длиннее 2048 символов (ограничение Credential Manager Windows). В Linux системное хранилище требует провайдер Secret Service поверх D-Bus: без него приложение создаёт безопасную переменную, но раскрытие отвечает пустотой, и секрет сохранить некуда — это ограничение плагина keyring, а не приложения. Ответы серверов не маскируются: если секрет попал в тело ответа, он показывается как есть. Удаление или переименование переменной не меняет сохранённые запросы — шаблоны в них остаются текстом и при отправке дают ошибку. Подстановка недоступна в браузерной сборке, поэтому запросы с шаблонами там блокируются.

## Обновления

Desktop-приложение обновляется через `tauri-plugin-updater` и статический манифест `latest.json` из GitHub Releases (`https://github.com/DimetriusJonson/dev_tools_svelte/releases/latest/download/latest.json`).

- **Автопроверка при старте** выполняется через 1,2 с после гидратации окна, чтобы не конкурировать с первой отрисовкой. Она молчит: баннер поднимается только если есть более новый релиз, который не был отклонён, а неудача уходит только в консоль — без красного баннера и уведомлений.
- **Кнопка «Проверить обновления»** в верхней панели (иконка «загрузка в коробку», во время проверки — вращающийся символ) доступна только в desktop-сборке. Ручная проверка всегда отвечает уведомлением: «Версия {version} — последняя», «Обновлений не найдено» или причина неудачи.
- **Баннер** появляется под верхней панелью: версия релиза, примечания из манифеста (если релиз их опубликовал), кнопка «Установить» и «Не сейчас». Во время загрузки показывается прогресс в процентах, и если манифест не сообщил размер — прогресс остаётся нулевым, а не притворяется полным. После установки баннер переходит в состояние «готово» с кнопкой «Перезапустить» и «Позже».
- **«Не сейчас» скрывает ровно эту версию**: она сохраняется в SQLite (`app_settings`, ключ `update.dismissedVersion`) и при автопроверке больше не показывается. Релиз с другой версией появляется снова, а ручная проверка показывает и отклонённую версию — отклонение не мешает проверить всё заново.
- **Установка на Windows**: `windows.installMode: "passive"` передаёт `msiexec /passive`, то есть установщик показывает только прогресс-бар и не требует кликов. Плагин запускает установщик отдельно: приложение закрывается до того, как обещание установки вернётся, а установщик сам запускает новую версию. Поэтому баннер остаётся в состоянии «Установка…» и показывает подсказку про установщик вместо кнопки «Перезапустить». На macOS и Linux артефакт заменяется на месте, и перезапуск делает кнопка «Перезапустить» (команда `restart_app` на бэкенде).
- **Ошибки группируются**: сборка без endpoint, endpoint по HTTP, неподдерживаемая ОС или архитектура дают «Обновления недоступны в этой сборке»; манифест ответил, но релиза для этой платформы в нём нет — информационное «Обновлений не найдено», а не красный баннер; прочие ошибки — красный баннер с текстом причины и кнопкой закрытия.
- **Подпись**: артефакты подписываются minisign-ключом, публичный ключ лежит в конфигурации, приватный — вне репозитория (`TAURI_SIGNING_PRIVATE_KEY`). `requireSignedVersion: true` отклоняет обновление, если версия в подписи не совпадает с версией из манифеста: манифест приходит по TLS, но сам не подписан, и без этого флага подделанный ответ мог бы указать завышенную версию и подставить URL и подпись старого, но подписанного релиза. Клиенты, подписанные до того, как CLI стал записывать версию в подпись, этот флаг тоже отклонят — такие релизы нужно переподписать.

Критерии: при доступном релизе баннер показывает версию и кнопки «Установить» / «Не сейчас»; «Не сейчас» скрывает баннер, автопроверка следующего запуска ту же версию больше не показывает, а релиз с другой версией показывается снова; если релиза для платформы нет, ручная проверка даёт информационное уведомление и не поднимает красный баннер; во время загрузки баннер показывает проценты, а без размера файла — 0%; в браузерной сборке ни кнопки проверки, ни автопроверки нет.

Ограничения: пока в GitHub Releases не лежат `latest.json`, установщик и `.sig`, проверка отвечает «Обновлений не найдено», и путь установки целиком не проверить; всё это кладёт workflow по тегу `v<версия>`, но сам релиз становится «последним» только после шага публикации, поэтому до него манифест по адресу `releases/latest/download/latest.json` ещё не читается. Обновления требуют доступа к `github.com`: без сети автопроверка молчит, а ручная показывает ошибку. Обновления доступны только в desktop-сборке — в браузере ни плагина, ни подписанных артефактов нет. Отклонённая версия хранится в SQLite и не синхронизируется между устройствами.

## Экран загрузки

Пока JS-бандл не загрузился и приложение не гидратировалось, окно показывало пустой экран. Экран загрузки описан прямо в `src/app.html`, поэтому он рисуется до выполнения бандла:

- логотип (`static/favicon.svg`), название приложения, спиннер и подпись о загрузке;
- номер версии и локализованное название из словаря проставляются при гидратации;
- тема выбирается тем же пред-гидрационным скриптом, что и всё остальное приложение, поэтому экран не мигает белым фоном;
- язык подписей берётся из `devtools.locale`, а при отсутствии значения — из локали ОС, так что первая надпись уже на нужном языке;
- экран виден минимум 350 мс, затем плавно гаснет за 260 мс и удаляется из DOM; повторный вызов ничего не делает;
- если бандл так и не запустил приложение, через 12 с под подписью появляется дополнительная подсказка перезапустить приложение.

Критерии: при открытии окна до гидратации виден экран с логотипом, названием и спиннером, а не пустой фон; при быстром запуске экран не мелькает; после гидратации экран исчезает и не перехватывает клики; темы и язык применяются к экрану так же, как к приложению. Нативный сплэш-скрин Tauri не используется.

## Навигация, темы и язык

- Верхняя панель содержит вкладки XML, JSON, URL, Compare, Share, Rest client и WSDL, а в desktop-сборке — круглую кнопку «Глобальные переменные» (иконка переменной, на странице `/global-vars` она получает акцентное кольцо) и кнопку проверки обновлений: она не подсвечивается фоном при наведении, как вкладки, во время проверки вращается и блокируется до её конца.
- Кнопки навигации увеличиваются при наведении (`hover:scale-105`); подсветка фона при наведении не используется.
- Переключатель языка: `en` / `ru`. По умолчанию выбирается системный язык: `ru`, если локаль ОС начинается с `ru`, иначе `en`.
- Переключатель темы циклически меняет режимы `system → dark → light`. По умолчанию используется `system`.
- Titles native file dialogs (choosing the input file, saving the formatted file, choosing a `Form` file part) and their filter labels follow the selected language: «Select XML file» / «Выбор XML файл», «All files» / «Все файли», «Select file to send» / «Выберите файл для отправки».
- Выбор языка и темы сохраняется в `localStorage`.

## Сохранение данных

В Tauri-режиме база данных создаётся в app data directory приложения:

```text
webdev-useful-tools.db
```

Используются таблицы:

- `editor_state` — содержимое и опции редакторов;
- `app_settings` — key/value-настройки: выбор проекта и запроса в Rest client (`rest.activeProject`, `rest.activeRequest`), выбор проекта и операции в WSDL-клиенте (`wsdl.activeProject`, `wsdl.activeOperation`), версия обновления, отклонённая кнопкой «Не сейчас» (`update.dismissedVersion`), срок хранения загрузок Share (`share.retention`: `none`, `1d`, `3d`, `7d`, `always`). Пустая строка у ключей выбора означает «ничего не выбрано». Тема и язык сейчас хранятся в `localStorage`;
- `shared_uploads` — общие файлы и текстовые фрагменты: UUID, имя, MIME-тип, BLOB, размер, время создания и `expires_at` — время окончания хранения (`NULL` означает «хранить всегда`). Строки с `expires_at` в прошлом не отдаются по ссылке и удаляются из базы при записи, чтении или старте сервера;
- `rest_projects` — проекты Rest client;
- `rest_requests` — сохранённые запросы: метод, URL, текстовое тело (буфер вкладок JSON/XML/Text), тип тела, флаг сохранения ответа, сохранённый ответ и отправленный запрос, открытые вкладки панелей (`request_tab`, `multipart_tab`, `response_tab`);
- `rest_request_properties` — HTTP-заголовки запроса (тип `header`);
- `rest_request_form` — строки таблицы вкладки `Form-encode` (`name`, `value`, порядок). Они хранятся отдельно от текстового тела, и закодированное тело больше не дублируется в `rest_requests.body`.
- `rest_request_multipart` — поля вкладки `Form` (`name`, `value`, порядок);
- `rest_request_files` — части с файлами (`name`, `path`, `filename`, порядок). В базе остаются путь и имя файла: содержимое файла не сохраняется, а выбранный в браузере объект `File` не попадает ни в `localStorage`, ни в SQLite.
- `global_vars` — глобальные переменные: UUID, имя, флаг `secure`, значение и порядок. У безопасной переменной колонка `value` всегда пустая — её значение живёт только в системном хранилище секретов. Имя уникально без учёта регистра (индекс `idx_global_vars_name`), список отдаётся по имени без учёта регистра.
- `wsdl_projects` — проекты WSDL-клиента;
- `wsdl_files` — импортированные документы: имя по URL, адрес выгрузки, исходный XML целиком и список предупреждений импорта (JSON-массив кодов);
- `wsdl_services` — службы (`wsdl:service`) импортированного файла;
- `wsdl_operations` — операции: `soapAction`, имена входного и выходного элементов и сгенерированный шаблон запроса;
- `wsdl_endpoints` — адреса `soap:address` операции с её версией SOAP (`1.1`/`1.2`), именем привязки и порта;
- `wsdl_operation_state` — состояние операции: выбранный адрес, изменённое тело, строки заголовков (JSON-массив `{name, value}` без locked-строк), флаг `save_response`, сохранённые ответ и отправленный запрос. Строка создаётся лениво при первом открытии операции.

Удаление проекта WSDL удаляет его файлы, а удаление файла — его службы, операции, адреса и состояния операций в одной транзакции. Locked-заголовки (`Content-Type`, `SOAPAction`) отдельным флагом не хранятся: их пересчитывают по версии SOAP и `soapAction` выбранного адреса. Повторный импорт того же адреса в тот же проект сохраняет `id` файла и операций, а также `id` адресов, совпавших по URL и версии, поэтому состояние операций переживает перезагрузку документа.

Проекты, запросы, заголовки, Form-encode и обе таблицы вкладки `Form` Rest client хранятся в отдельных таблицах. Удаление проекта не удаляет запросы: они остаются в списке без привязки к проекту (`project_id = NULL`), а фильтр проектов показывает «Не выбран». Удаление запроса удаляет его заголовки, строки Form-encode, поля и части с файлами.

Ключи `editor_state`:

- `xml`, `json` — исходный контент, отступ и чекбоксы;
- `url` — исходная строка;
- `compare-left`, `compare-right` — обе стороны сравнения.

Сохранение выполняется с задержкой 450 мс после изменения (в Compare — 500 мс). Если приложение запущено вне Tauri, используется `localStorage` с префиксами `devtools.editor.` и `devtools.setting.`.

## Desktop-интеграция

- **Single instance** — второй экземпляр приложения фокусирует и разворачивает уже открытое окно.
- **Трей** — пункты «Открыть» и «Выход».
- **Закрытие окна** — скрывает окно в трей; полностью приложение завершается через «Выход» в трее.
- **Файловые диалоги** — `@tauri-apps/plugin-dialog`.
- **Хранилище секретов** — `tauri-plugin-keyring` (только из Rust) хранит значения безопасных глобальных переменных в системном хранилище: service `app.webdev.usefultools.global-vars`, аккаунт — `id` переменной. Отдельного capability для него нет, и в SQLite такие значения не попадают.
- **Share-сервер** — `axum` слушает `0.0.0.0:3030` и отдаёт только GET-запросы.
- **Deep links** — схема `webdev-useful-tools` регистрируется через `tauri-plugin-deep-link`; второй экземпляр передаёт ссылку уже запущенному приложению через `single-instance` с feature `deep-link`.
- **Обновления** — `tauri-plugin-updater` с endpoint на GitHub Releases и подписью minisign; на Windows установщик запускается с `/passive` и перезапускает приложение сам, вне Windows перезапуск идёт командой `restart_app` через `request_restart`, чтобы события `RunEvent::ExitRequested`/`Exit` успели остановить Share-сервер. Плагин добавляет capability `updater:default`; отдельный `tauri-plugin-process` для перезапуска не используется.
- **Иконки** — исходник `src-tauri/icon-source.png`, SVG-версия `src-tauri/icons/app-icon.svg`; набор иконок сгенерирован через `npx tauri icon`.

Размер окна по умолчанию — 1440×920, минимальный — 1100×700.

Утилиты обновлений покрыты тестами: проценты загрузки (в том числе 0% при неизвестном размере), отклонённая версия, группировка ошибок плагина на «недоступно», «не найдено» и «сбой» и распознавание Windows по user agent. Additional frontend coverage: cURL flags `-b`, `-A`, `-e`, `-u`, `--url`, `--data-urlencode`; short ANSI-C `$'…'` escapes; helpers `getHeader`, `bodyTypeFromContentType`, `defaultContentType`, `multipartBoundary`; code points outside the range and surrogates (`&#xD800;`, `&#x110000;`, `\uD800`) in entity decoding, JSON unescape and format XML/JSON do not throw exceptions and stay as their own text; display name and content type of preview part multipart read from file path; path helpers `basename`, `formattedPath`, `sharedFileName` (a server-supplied name reduced to one safe file name); dictionaries `en`/`ru` (same set keys, same set placeholders each key); notification stack (only the latest stay on screen, a failure without text uses localized `common.error`); `resolveRestSelection` for `request_id` `null`; `normalizeUrl` (query containing `://`, non-http(s) scheme, empty string); редактор CodeMirror подсвечивает HTML-разметку — имя тега, имя атрибута и его значение получают три разных стиля подсветки, а обычный текст не получает ни одного. Rust-тесты покрывают SQLite, маппинг действий трея, форматирование контента (в том числе толерантный разбор битой разметки и битого JSON и обработку файла с битой разметкой), обработку файлов, share-хранилище (round trip загрузки с UUID v4, добавление колонки `expires_at` в старую базу, сроки хранения и очистка просроченных строк, удаление загрузки и пустой ответ для неизвестного ID, стирание строки, которую чтение уже скрыло), deep link validation (в том числе ссылку без токена и лишние параметры), parse_retention, вытеснение самого старого содержимого в памяти, состояние HTTP-сервера и маршруты сервера (GET просмотрщика, raw-загрузка с `Content-Disposition`, 404 для неизвестного или битого ID, DELETE один раз и повторный 404, отдача и удаление содержимого из памяти), CRUD проектов и запросов Rest client, кодирование multipart-тела с boundary, dump предпросмотра и round trip полей и файлов через SQLite, имя файла из `Content-Disposition` (форма `filename*` сильнее обычной), round trip `reqwest` по plain HTTP и определение HTML по типу содержимого и по телу (`application/xhtml+xml` даёт HTML, а не XML; документ по тегу или по `<!DOCTYPE html`). Общие хелперы проверки значений по RFC (`utils/validation.ts`) покрыты тестами отдельно: они дают обе страницы — Rest client и WSDL-клиент — один и тот же текст причины.

WSDL-клиент покрыт тестами на обоих слоях. Vitest проверяет сборку SOAP-конверта для 1.1 и 1.2, канонические locked-заголовки и отбрасывание пользовательских дубликатов, выбор адреса из списка `soap:address`, нормализацию строк заголовков, сохранение только редактируемых строк, восстановление выбора проводника (в том что операция из другого проекта уводит проводник в тот проект) и перевод кодов ошибок и предупреждений импорта в локализованные ключи. Rust-тесты проверяют схему SQLite, парсер WSDL 1.1 (несколько `port` и `binding`, SOAP 1.2, отсутствие `soap:address` и привязки, WSDL 2.0, документ без операций, битый XML, превышение глубины и числа элементов), генератор шаблона по XSD (`sequence`, `all`, `choice`, `extension`, `ref`, `minOccurs`/`maxOccurs`, `nillable` не добавляет комментария, наследование — `complexContent` с `extension` и `restriction` и `simpleContent` с атрибутами, где поля базы идут первыми, а добавленные элементы и атрибуты после них, и базовый встроенный тип не даётся как неразрешённый, рекурсивный тип, неразрешённый тип, пределы глубины и числа элементов, метки `Optional:` и повторов над открытыми блоками, `?` вместо подставленных образцов, атрибуты внутри тега и отсутствие подсказки про `xsi:nil`, один комментарий на строку без вложенных маркеров, сохранение отступов закомментированной ветки и читаемость всего шаблона как XML) и хранилище (создание и переименование проектов, каскадное удаление, повторный импорт без потери состояния, ленивое создание состояния, пересчёт locked-строк при чтении состояния, ответ и тело запроса не затирают друг друга, конфликт `UNIQUE(project_id, source_url)`). Общие для двух страниц подсказки таблиц и текст блокировки (`utils/validation.ts`) покрыты тестами отдельно, чтобы Rest client и WSDL-клиент показывали одну и ту же причину.

Глобальные переменные покрыты тестами на обоих слоях. Vitest проверяет сканер шаблонов (имена без повторов, вложенные `{{`, плохие имена вроде `{{ a b }}` и `{{1}}`), правила имени и уникальности без учёта регистра, список мест, где подстановка допустима (query, заголовки, тело, Form-encode, поля `Form`) и где она не работает, что буфер тела и строки `Form` читаются только для своей вкладки, что шаблон в хосте, пути, имени параметра и в имени заголовка считается шаблоном (в percent-коде тоже), перевод кодов ошибок бэкенда в локализованные ключи, в том числе `invalid-value:`, desktop-only guard сервиса и страницу: маскировку безопасного значения, раскрытие и автоматическое скрытие, запись раскрытого секрета после debounce, запись секрета, набранного в последние 450 мс до истечения окна, создание из черновика с сохранением типа, отказ по неверному имени, двухшаговое удаление с отменой незаписанной правки, подтверждение перевода безопасной переменной в базу с тем значением, что было набрано перед кликом, надписью «Значение ещё не сохранено» для безопасной строки без секрета, сохранением введённого текста и причины при отказе хранилища секретов и тем значением, которое уходит в базу при переводе безопасной переменной в обычную. Rust-тесты проверяют CRUD переменных, что у безопасной строки колонка `value` остаётся пустой и секрет живёт только в хранилище, перенос значения при смене типа, создание безопасной переменной с пустым значением без записи в хранилище и очистку раскрытого секрета, что переименование не трогает аккаунт хранилища, что конфликт `UNIQUE` возвращается как `duplicate-name:` с именем в исходном регистре, лимит 2048 байт, подстановку в query, заголовки, тело, Form-encode и поля multipart, маскировку сохранённого дампа `********` с `Content-Length` самого дампа, отказ для шаблона в пути URL, имени параметра или имени заголовка, отказ шаблона в буфере, который не уходит в сеть, и отказ управляющего символа в подставленном значении заголовка или поля.

## Ограничения

- Share работает только в desktop-приложении и только с устройствами, которые могут достучаться до `0.0.0.0:3030` в локальной сети. Loopback-адрес доступен только на самом устройстве.
- HTTP-сервер Share не использует авторизацию и у ссылки нет токена: любой, кто знает UUID и адрес, может прочитать загрузку и удалить её, пока приложение запущено и срок хранения не истёк. Ссылки не следует публиковать во внешних сетях.
- Загрузки Share имеют срок хранения только если он выбран: «Всегда» остаётся в базе до удаления из просмотрщика, «Не хранить» вообще не попадает в базу и живёт только до закрытия приложения, а в памяти удерживается не более 24 последних таких загрузок — самая старая вытесняется раньше, чем ссылка успевает открыться.
- Возможности Rest client в браузере ограничены CORS и запрещёнными заголовками; для полноценной работы используйте desktop-сборку.
- Проверка заголовков, query, Form-encode и `Form` (multipart) выполняется на клиенте: она блокирует выполнение запроса, копирование cURL и скачивание ответа, но не переписывает значения за пользователя — исправить нужно вручную. Символы non-ASCII в значениях заголовков не запрещаются. Имена файлов в частях не проверяются: кодирующий модуль очищает их сам и ставит `filename*=UTF-8''…`, когда имя содержит символы вне ASCII.
- Строки заголовков, `Form-encode` и `Form` без названия не сохраняются в SQLite и исчезают после перезапуска приложения; значения `Query` и `Cookies` при этом остаются в URL и в заголовке `Cookie`, поэтому такая строка восстановится и по-прежнему будет подсвечена.
- Parts вкладки `Form` читаются с диска во время выполнения запроса, поэтому перед отправкой файл должен быть доступен по сохранённому пути; содержимое файлов в базу не пишется.
- Rest client хранит сохранённые ответы в SQLite без ограничения размера; очень большие ответы могут замедлить интерфейс.
- WSDL-клиент доступен только в desktop-сборке и понимает только WSDL 1.1 с привязками SOAP 1.1 и SOAP 1.2: WSDL 2.0, HTTP/XML- и MIME-привязки отклоняются или помечаются предупреждением. Внешние `xsd:import` и `xsd:include` не выгружаются, поэтому типы из чужих пространств имён остаются в шаблоне комментарием.
- Шаблон запроса — отправная точка, а не валидатор: приложение не проверяет заполненное тело по схеме и не исправляет его. Глубина шаблона ограничена 32 уровнями, число элементов — 2000, рекурсивные типы обрезаются, и оба предела показываются предупреждением файла.
- Файл WSDL выгружается целиком в память с лимитом 5 МБ и таймаутом 30 с; внешние сущности XML не читаются.
- Ответ операции сохраняется в базе только при включённом чекбоксе `Save` и только текстовый: вложение и бинарный ответ скачиваются на диск, но между запусками не хранятся. Из страницы WSDL вызов не экспортится как cURL — вкладка `Raw` показывает обмен и копируется текстом; предпросмотра HTML, как в Rest client, здесь нет.
- Обновления есть только в desktop-сборке и требуют доступа к `github.com`. Пока к релизу не приложены `latest.json`, установщик и `.sig`, проверка отвечает «Обновлений не найдено», и установить ничего нельзя. На Windows установщик закрывает приложение и перезапускает его сам, поэтому результат установки в баннере не показывается; если установщик не завершился, та же версия предложится снова при ручной проверке.
- Глобальные переменные работают только в desktop-сборке: подставку делает Rust-бэкенд, а безопасные значения читаются из системного хранилища секретов, недоступного браузеру. Безопасное значение ограничено 2048 символами, в дампе отправленного запроса оно скрыто как `********` вместе с длиной дампа, но ответы серверов не маскируются — попавший в ответ секрет показывается как есть. В Linux хранилище требует провайдер Secret Service поверх D-Bus (GNOME Keyring или KWallet): без него раскрытие отвечает пустотой, а не ошибкой, поэтому секрет в такой системе сохранить нельзя.
- Обработка больших файлов доступна только в Tauri-сборке.
- Compare использует ограниченный по памяти LCS и для очень больших блоков применяет упрощённое сравнение.
- Тема и язык хранятся в `localStorage`, а не в SQLite.
- Экран загрузки рисуется из HTML-шаблона, поэтому до получения `index.html` окно ещё пустое: нативного сплэш-скрина Tauri нет, и текст подписей экрана дублирует словарь i18n (название при гидратации всё равно берётся из него).
